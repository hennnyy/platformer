# 2D 플랫포머 게임 디자인

## 1. 문서 상태

- 상태: 첫 번째 수직 슬라이스 기준 확정안
- 대상: 2D 횡스크롤 싱글플레이 플랫포머
- 첫 플랫폼: PC
- 예상 플레이 시간: 첫 스테이지 5~10분
- 관련 문서: [ARCHITECTURE.md](./ARCHITECTURE.md)
- 최소 구현 범위: [MVP_SCOPE.md](./MVP_SCOPE.md)

이 문서는 첫 번째 플레이 가능한 버전에서 무엇을 만들고 무엇을 만들지 않을지 결정한다. 세계관, 캐릭터 이름, 그래픽 테마는 아트 방향이 정해진 뒤 교체할 수 있도록 임시 요소로 취급한다.

---

## 2. 게임 한 줄 설명

정교하지만 관대한 이동 조작으로 장애물과 적을 돌파하고, 체크포인트를 거쳐 스테이지의 도착점에 도달하는 2D 플랫포머 게임이다.

---

## 3. 플레이 경험 목표

### 핵심 기둥

1. **즉시 반응하는 이동**
   - 입력과 캐릭터 반응 사이의 지연이 느껴지지 않아야 한다.
   - 가속과 감속은 존재하지만 원하는 위치에 정확히 멈출 수 있어야 한다.

2. **실수를 받아주는 점프**
   - 코요테 타임과 점프 버퍼를 기본 제공한다.
   - 점프 버튼을 누르는 길이에 따라 높이가 달라진다.
   - 실패 이유를 플레이어가 이해할 수 있어야 한다.

3. **짧은 도전과 빠른 재시도**
   - 위험 구간 하나는 5~15초 안에 통과할 수 있게 구성한다.
   - 사망 후 2초 안에 다시 조작할 수 있는 것을 목표로 한다.
   - 체크포인트 사이에서 반복되는 이동 시간을 최소화한다.

### 플레이 감정의 흐름

```text
관찰 → 이동 경로 선택 → 실행 → 즉각적인 피드백 → 성공 또는 빠른 재도전
```

첫 스테이지는 이 흐름을 여러 번 반복하면서 이동, 점프, 적 회피, 체크포인트, 도착점을 자연스럽게 학습시키는 역할을 한다.

---

## 4. 대상 플레이어와 난이도

- 플랫포머를 처음 접하는 사람도 첫 스테이지를 완료할 수 있어야 한다.
- 장르 경험자는 이동을 끊지 않고 빠르게 통과할 수 있어야 한다.
- 기본 난이도에서는 정확한 프레임 단위 입력을 요구하지 않는다.
- 첫 스테이지의 예상 사망 횟수는 신규 플레이어 기준 3~8회로 잡는다.

난이도는 적의 체력 증가보다 지형과 위험 요소의 조합으로 높인다. 화면 밖에서 갑자기 등장하는 위험이나 사전 정보 없이 죽는 배치는 사용하지 않는다.

---

## 5. 핵심 게임 루프

```text
스테이지 시작
  → 주변과 목적지 확인
  → 이동·점프로 짧은 구간 돌파
  → 적 또는 수집물과 상호작용
  → 체크포인트 도달
  → 더 복합적인 구간 돌파
  → 도착점 도달
  → 결과 확인 및 다음 스테이지 해금
```

실패 루프는 다음과 같다.

```text
피격 또는 낙사
  → 체력이 남으면 짧은 무적 후 계속 진행
  → 사망하면 최근 체크포인트에서 빠르게 재시작
```

---

## 6. 조작 방식

### 기본 입력

| 행동 | 키보드 기본값 | 게임패드 기본값 | 입력 형태 |
|---|---|---|---|
| 이동 | `A` / `D`, 방향키 | 왼쪽 스틱, D-pad | 연속 |
| 점프 | `Space` | 남쪽 버튼 | 누름/유지/뗌 |
| 아래로 통과 | `ctrl` |  `ctrl`|  누름|
| 일시정지 | `Esc` | Start/Menu | 누름 |
| 확인 | `Enter` / `Space` | 남쪽 버튼 | 누름 |
| 취소 | `Esc` | 동쪽 버튼 | 누름 |

첫 번째 수직 슬라이스에는 공격, 대시, 벽 점프 입력을 추가하지 않는다. 입력 재지정 화면은 후속 단계에서 구현하되, 입력 코드는 처음부터 행동 이름을 통해 장치와 분리한다.

### 조작 규칙

- 좌우 입력이 없으면 지상에서 빠르게 감속한다.
- 공중에서도 방향을 수정할 수 있지만 지상보다 반응을 약하게 한다.
- 점프 버튼을 짧게 누르면 낮게, 길게 누르면 높게 점프한다.
- 발판 끝을 벗어난 직후에도 짧은 시간 동안 점프할 수 있다.
- 착지 직전에 누른 점프는 착지 직후 자동 실행된다.
- 단방향 발판에서는 아래 입력과 점프 입력을 조합해 내려간다.

## 7. 플레이어 규칙

### 기본 능력

| 능력 | 수직 슬라이스 | 설명 |
|---|---:|---|
| 걷기/달리기 | 포함 | 별도 달리기 버튼 없이 한 가지 이동 속도 사용 |
| 점프 | 포함 | 가변 높이, 코요테 타임, 입력 버퍼 지원 |
| 단방향 발판 통과 | 포함 | 아래 방향과 점프 조합 |
| 피격과 넉백 | 포함 | 짧은 조작 제한과 무적 시간 |
| 체크포인트 리스폰 | 포함 | 사망 후 최근 체크포인트에서 복귀 |
| 공격 | 제외 | 적은 밟거나 피하는 방식으로 처리할 수 있음 |
| 대시 | 제외 | 기본 이동 검증 이후 후보 기능 |
| 벽 점프 | 제외 | 레벨 구조를 크게 바꾸므로 후속 검토 |

### 체력과 피격

- 최대 체력: 3
- 일반 위험 요소의 피해: 1
- 낙사: 즉시 사망
- 피격 무적 시간: 1.0초부터 튜닝 시작
- 피격 시 안전한 방향으로 짧게 넉백
- 무적 중에는 캐릭터가 점멸하고 피격 판정을 무시함
- 피격 직후 0.15~0.25초 범위의 짧은 조작 제한을 검토함

체력이 0이 되면 사망한다. 스테이지 중 체력 회복 아이템은 첫 스테이지에 최대 1개만 배치한다.

### 적과의 상호작용

첫 번째 적은 단순 순찰형이다.

- 옆면이나 아래에서 접촉하면 플레이어가 피해를 받는다.
- 위에서 밟으면 적이 제거되고 플레이어는 작게 튀어 오른다.
- 이 규칙은 별도의 공격 버튼 없이도 적을 상대할 선택지를 제공한다.
- 적을 반드시 제거해야만 진행되는 구간은 첫 스테이지에서 사용하지 않는다.

## 8. 성공과 실패 조건

### 스테이지 성공

플레이어가 도착점 트리거에 들어가면 스테이지를 클리어한다.

클리어 시 다음을 처리한다.

- 플레이어 입력 잠금
- 짧은 클리어 연출
- 소요 시간과 수집물 결과 표시
- 스테이지 클리어 상태 저장
- 다음 스테이지 해금
- 다시 하기, 다음 스테이지, 메인 메뉴 선택 제공

첫 번째 버전에서는 수집물을 모두 모아야 클리어되는 조건을 사용하지 않는다.

### 실패

다음 경우 플레이어가 사망한다.

- 체력이 0이 됨
- 낙사 경계에 진입함
- 즉사 위험 요소에 닿음

일반 사망은 게임 오버가 아니라 최근 체크포인트에서의 재시작으로 처리한다. 생명 수나 재시도 횟수 제한은 두지 않는다.

---

## 9. 첫 번째 스테이지 구성

### 목적

첫 스테이지는 텍스트 튜토리얼에 의존하지 않고 플레이를 통해 규칙을 가르친다. 한 번에 하나의 새 요소를 소개하고, 안전한 연습 뒤에 조합 구간을 제공한다.

### 구간 설계

| 구간 | 예상 시간 | 새로 소개하는 요소 | 실패 위험 |
|---|---:|---|---|
| A. 시작 지대 | 30~60초 | 좌우 이동, 기본 점프 | 없음 또는 매우 낮음 |
| B. 발판 지대 | 60~90초 | 점프 높이 조절, 단방향 발판 | 낮음 |
| C. 위험 지대 | 60~90초 | 가시, 낙사, 빠른 리스폰 | 중간 |
| D. 적 지대 | 60~120초 | 순찰형 적, 밟기 | 중간 |
| E. 체크포인트 | 10~20초 | 활성화와 피드백 | 없음 |
| F. 조합 지대 | 90~180초 | 발판, 가시, 적의 조합 | 중간~높음 |
| G. 도착 지대 | 20~40초 | 목표 진입과 클리어 | 낮음 |

### 배치 원칙

- 시작 지점에서 진행 방향과 첫 번째 안전 지형이 보이게 한다.
- 새 위험 요소는 먼저 안전하게 관찰할 수 있게 보여준다.
- 블라인드 점프가 필요한 경우 착지 지점을 카메라로 먼저 보여준다.
- 체크포인트 직후에는 바로 죽게 만드는 함정을 배치하지 않는다.
- 어려운 조합 앞에는 플레이어가 멈춰 관찰할 공간을 둔다.
- 도착점은 입구에서 시각적으로 구분되고 접근 시 별도의 효과를 제공한다.

### 수집물

첫 스테이지에는 선택 경로를 유도하는 수집물 5개를 배치한다.

- 필수 진행 경로: 2개
- 약간의 탐색이나 점프 정밀도를 요구하는 경로: 2개
- 스테이지의 숙련된 이동을 요구하는 경로: 1개

수집물은 점수 경쟁보다 경로 안내와 재플레이 동기 제공을 우선한다. 수집 여부는 스테이지 기록에 저장한다.

## 10. 적과 환경 요소

### 순찰형 적

| 항목 | 규칙 |
|---|---|
| 이동 | 일정 속도로 좌우 순찰 |
| 방향 전환 | 벽 또는 낭떠러지 감지 시 전환 |
| 공격 | 접촉 피해 |
| 약점 | 위에서 밟기 |
| 체력 | 밟기 1회 |
| 리스폰 | 플레이어 사망으로 스테이지 리셋 시 복원 |

플레이어가 적의 이동 방향을 읽을 수 있도록 방향 전환과 피격에 명확한 애니메이션 및 소리를 제공한다.

### 환경 요소

| 요소 | 역할 | 초기 규칙 |
|---|---|---|
| 일반 지형 | 이동 기반 | 완전 충돌 |
| 단방향 발판 | 수직 경로 제공 | 아래에서 통과 가능 |
| 가시 | 타이밍/거리 판단 | 피해 1, 짧은 넉백 |
| 낙사 구역 | 경로 이탈 처벌 | 즉시 사망 |
| 체크포인트 | 진행 보존 | 접촉 시 활성화 |
| 도착점 | 스테이지 종료 | 접촉 시 클리어 |

움직이는 발판은 기본 이동과 고정 지형 충돌이 안정된 후 추가한다.

## 11. 카메라와 화면 정보

### 카메라 목표

- 플레이어 진행 방향의 지형을 충분히 보여준다.
- 점프 중 착지 위치가 화면에 유지되게 한다.
- 빠른 방향 전환 시 화면이 과도하게 흔들리지 않게 한다.
- 스테이지 밖이나 미완성 영역을 보여주지 않는다.

### HUD

게임 중 항상 표시할 정보는 최소화한다.

- 현재 체력
- 수집한 수집물 수 / 스테이지 전체 수
- 일시정지 진입 안내는 첫 구간에서만 선택적으로 표시

스테이지 소요 시간은 플레이 중 항상 노출하지 않고 결과 화면에서 보여준다. 추후 타임어택 모드가 생기면 설정으로 표시할 수 있다.

---

## 12. 피드백 규칙

모든 중요한 행동은 시각, 소리, 움직임 중 최소 두 가지 방식으로 피드백한다.

| 행동 | 시각 피드백 | 소리/움직임 피드백 |
|---|---|---|
| 점프 | 자세 변화, 먼지 효과 | 점프 효과음 |
| 착지 | 착지 자세, 작은 먼지 | 착지 효과음, 약한 카메라 반응 |
| 피격 | 점멸, 피격 효과 | 피격음, 넉백, 화면 흔들림 |
| 적 밟기 | 적 제거 효과 | 반동 점프, 타격음 |
| 수집 | 빛/입자, HUD 변화 | 수집 효과음 |
| 체크포인트 | 색 또는 형태 변화 | 활성화 효과음 |
| 사망 | 사망 애니메이션, 페이드 | 사망 효과음 |
| 클리어 | 도착점 연출, 결과 UI | 클리어 음악 또는 효과음 |

카메라 흔들림, 화면 점멸, 강한 파티클은 설정에서 강도를 낮추거나 끌 수 있도록 확장 가능하게 만든다.

## 13. 초기 밸런스 목표

다음 값은 구현 시작점이며 플레이 테스트로 조정한다. 실제 JavaScript 구현 단위는 `PLAYER_MOVEMENT.md`에서 확정한다.

| 항목 | 목표 |
|---|---:|
| 정지 상태에서 최대 속도 도달 | 0.10~0.20초 |
| 최대 속도에서 정지 | 0.08~0.18초 |
| 기본 점프 체공 시간 | 0.65~0.90초 |
| 코요테 타임 | 0.08~0.12초 |
| 점프 입력 버퍼 | 0.10~0.15초 |
| 피격 무적 시간 | 약 1.0초 |
| 사망 후 조작 복귀 | 2초 이내 |
| 체크포인트 간 플레이 | 1~3분 |

숫자를 고정값으로 간주하지 않고 목표 감각을 재현하기 위한 시작 범위로 사용한다.

## 14. 접근성 기본 기준

- 키보드와 게임패드를 모두 지원한다.
- 중요한 정보는 색상만으로 구분하지 않는다.
- HUD 텍스트와 아이콘은 일반 플레이 거리에서 읽을 수 있어야 한다.
- 화면 흔들림과 강한 화면 효과를 줄일 수 있는 설정을 고려한다.
- 게임 진행에 빠른 버튼 연타를 요구하지 않는다.
- 일시정지 상태에서 조작 방법을 다시 확인할 수 있게 한다.

입력 재지정, 자막, 고대비 옵션의 구체적인 범위는 수직 슬라이스 이후 확정한다.

---

## 15. 저장과 기록

첫 번째 버전에서 저장할 항목은 다음과 같다.

- 스테이지 클리어 여부
- 다음 스테이지 해금 여부
- 스테이지별 수집물 획득 여부
- 스테이지별 최고 기록 시간
- 오디오와 화면 설정

체크포인트는 현재 플레이 세션 안에서만 유지한다. 게임을 종료한 뒤 체크포인트에서 이어하기는 첫 번째 범위에서 제외한다.

---

## 16. 수직 슬라이스 범위

### 반드시 포함

- 플레이 가능한 스테이지 1개
- 이동, 가변 점프, 코요테 타임, 점프 버퍼
- 체력, 피격, 무적, 사망, 리스폰
- 일반 지형, 단방향 발판, 가시, 낙사 구역
- 순찰형 적 1종
- 수집물 5개
- 체크포인트 1개 이상
- 도착점과 클리어 결과
- HUD와 일시정지
- 키보드 및 게임패드 입력
- 모바일 터치 이동·점프·재시작 입력
- 기본 애니메이션, 효과음, 카메라

### 명시적으로 제외

- 온라인 및 로컬 멀티플레이
- 전투 콤보와 원거리 공격
- 대시와 벽 점프
- 보스전
- 인벤토리, 장비, 상점
- 퀘스트와 대화 시스템
- 절차적 스테이지 생성
- 체크포인트 영구 저장
- 모바일 전용 레벨 분기와 기기별 별도 콘텐츠

제외 항목은 수직 슬라이스의 플레이 테스트가 끝난 뒤 우선순위를 다시 평가한다.

---

## 17. 완료 판정 기준

다음 조건을 모두 만족하면 첫 번째 수직 슬라이스를 완료한 것으로 본다.

- 새 플레이어가 별도 설명 없이 이동과 점프를 익힐 수 있다.
- 스테이지 시작부터 클리어 결과 화면까지 중단 없이 진행된다.
- 낙사와 체력 사망 모두 최근 체크포인트에서 정상 복귀한다.
- 키보드와 게임패드로 동일한 기능을 사용할 수 있다.
- 30fps, 60fps, 120fps 환경에서 점프 결과가 의미 있게 달라지지 않는다.
- 플레이어가 벽이나 발판에 끼어 진행 불능이 되는 알려진 구간이 없다.
- 사망 후 2초 안에 다시 플레이할 수 있다.
- 수집물과 클리어 기록이 저장 후 다시 로드된다.
- 일시정지 중 게임플레이 시간이 흐르지 않는다.
- 디버그 로그에 반복 오류가 발생하지 않는다.

---

## 18. 플레이 테스트 질문

테스트 참가자에게 수치뿐 아니라 다음 질문의 답을 수집한다.

1. 캐릭터가 입력한 대로 움직인다고 느꼈는가?
2. 점프 실패 원인을 이해할 수 있었는가?
3. 다시 시도하기까지 기다림이 길다고 느꼈는가?
4. 어디로 가야 할지 모르는 순간이 있었는가?
5. 위험 요소를 충돌 전에 알아볼 수 있었는가?
6. 체크포인트가 충분히 자주 등장했는가?
7. 가장 재미있던 구간과 답답했던 구간은 어디였는가?

플레이 기록에서는 스테이지 완료 시간, 사망 위치, 사망 원인, 체크포인트별 재시도 횟수를 확인한다.
