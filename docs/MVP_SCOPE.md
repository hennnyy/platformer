# 최소 MVP 범위

## 1. 목표

최소 MVP의 목적은 2D 플랫포머의 핵심인 **이동과 점프가 재미있는지** 가장 작은 실행 가능한 게임으로 검증하는 것이다.

플레이어는 하나의 짧은 스테이지에서 이동과 점프로 장애물을 통과하고 도착점에 도달해야 한다. 낙사하면 시작 지점에서 즉시 다시 시도한다.

관련 문서:

- [ARCHITECTURE.md](./ARCHITECTURE.md)
- [GAME_DESIGN.md](./GAME_DESIGN.md)
- [PLAYER_MOVEMENT.md](./PLAYER_MOVEMENT.md)

---

## 2. 기술 선택

별도 게임 엔진, 프레임워크, 외부 라이브러리를 사용하지 않는다.

| 항목 | 선택 | 이유 |
|---|---|---|
| 실행 환경 | 데스크톱 웹 브라우저 | 별도 설치 없이 바로 실행 가능 |
| 게임 코드 | 순수 JavaScript | 빌드 도구 없이 작성·실행 가능 |
| 화면 | HTML5 Canvas 2D API | 브라우저 기본 기능으로 2D 렌더링 가능 |
| UI | HTML + CSS | 조작 안내와 결과 화면을 단순하게 구현 가능 |
| 입력 | Keyboard Event + Pointer Events API | 키보드와 모바일 멀티터치를 직접 처리 |
| 애니메이션 루프 | `requestAnimationFrame` | 브라우저 화면 갱신 주기와 동기화 |
| 첫 대상 | PC 및 모바일의 최신 브라우저 | 키보드와 터치 조작을 함께 검증 |

초기 버전은 npm, 번들러, TypeScript, React, 물리 라이브러리 없이 실행한다. `index.html`을 브라우저에서 열면 바로 플레이할 수 있게 구성한다.

---

## 3. 플레이 가능한 흐름

```text
index.html 열기
  → 테스트 스테이지 즉시 시작
  → 이동과 점프로 장애물 통과
  → 낙사 시 시작 지점에서 즉시 재시작
  → 도착점 진입
  → 클리어 문구 표시
  → R 키로 다시 플레이
```

메인 메뉴, 스테이지 선택, 저장 및 옵션 화면은 MVP에 포함하지 않는다.

---

## 4. 반드시 포함할 기능

### 플레이어

- 좌우 이동
- 점프
- 점프 키 유지 시간에 따른 높이 변화
- 코요테 타임
- 점프 입력 버퍼
- 바닥과 벽의 사각형 충돌
- 낙사 후 시작 지점 리스폰
- 진행 방향을 확인할 수 있는 단색 도형 표현
- 모바일용 왼쪽·오른쪽·점프·재시작 터치 버튼

### 스테이지

- 1~2분 길이의 그레이박스 스테이지 1개
- 사각형으로 구성한 평지와 고정 발판
- 높이가 다른 발판
- 넘어서야 하는 틈 2개 이상
- 화면 아래 낙사 판정
- 시작 지점과 도착점
- 맵 범위를 벗어나지 않는 카메라

### 화면 정보

- 조작법: `A/D` 또는 방향키, `Space`, `R`
- 클리어 문구
- 개발 모드에서 속도, 접지 상태, FPS 표시

---

## 5. MVP에서 제외할 기능

- 적과 공격
- 체력, 피격, 무적 시간
- 체크포인트
- 수집물
- 경사면, 단방향 및 움직이는 발판
- 스프라이트와 복잡한 애니메이션
- 파티클과 화면 흔들림
- 배경 음악과 효과음
- 메인 메뉴와 일시정지 메뉴
- 스테이지 선택과 다음 스테이지
- 영구 저장
- 게임패드 지원
- 대시, 벽 점프, 이단 점프

위 기능은 MVP 이동 테스트를 통과한 뒤 수직 슬라이스 단계에서 추가한다.

## 6. 최소 화면 구조

```text
index.html
└─ game-container
   ├─ canvas#game
   ├─ div#instructions
   ├─ pre#debug
   ├─ div#mobile-controls
   └─ div#clear-screen
```

- `canvas`: 게임 월드와 플레이어를 그린다.
- `instructions`: 조작법을 표시한다.
- `debug`: 개발 중 물리 값을 표시한다.
- `mobile-controls`: 터치 기기에서 이동, 점프, 재시작 버튼을 표시한다.
- `clear-screen`: 도착점 진입 후 결과와 재시작 안내를 표시한다.

## 7. 최소 파일 구조

```text
prj-platformer/
├─ index.html
├─ styles.css
├─ src/
│  └─ game.js
└─ docs/
   ├─ ARCHITECTURE.md
   ├─ GAME_DESIGN.md
   ├─ MVP_SCOPE.md
   └─ PLAYER_MOVEMENT.md
```

MVP에서는 모든 런타임 코드를 `game.js` 하나에 둔다. 파일 안의 섹션은 다음 순서로 나눈다.

```text
설정 상수
→ 입력 상태
→ 레벨 데이터
→ Player 클래스
→ 충돌 함수
→ Game 클래스
→ 초기화 코드
```

코드가 약 500줄을 넘거나 두 번째 스테이지를 만들게 되면 `input.js`, `player.js`, `collision.js`, `level.js`, `game.js`로 분리한다. MVP 전에 미리 분리하지 않는다.

## 8. 입력 매핑

| 행동 | 키보드 입력 | 모바일 입력 | 코드에서 사용할 이름 |
|---|---|---|---|
| 왼쪽 이동 | `A`, `ArrowLeft` | `←` 버튼 | `left` |
| 오른쪽 이동 | `D`, `ArrowRight` | `→` 버튼 | `right` |
| 점프 | `Space` | `JUMP` 버튼 | `jump` |
| 재시작 | `R` | `↻` 버튼 | `restart` |
| 디버그 표시 | `` ` `` | 없음 | `toggleDebug` |

`keydown`과 `keyup`에서 실제 키를 게임 행동으로 변환한다. 물리 계산은 키보드 이벤트 안에서 실행하지 않고 게임 루프에서 현재 입력 상태를 읽어 처리한다.

모바일 버튼은 Pointer Events로 처리하며 각 손가락의 `pointerId`를 따로 보관한다. 따라서 이동과 점프를 동시에 누를 수 있고, 시스템 제스처로 입력이 취소되면 눌린 상태도 함께 해제된다.

방향키와 Space 입력 시 페이지 스크롤이 일어나지 않도록 게임 키에 한해서 `event.preventDefault()`를 호출한다.

## 9. 게임 루프

렌더링에는 `requestAnimationFrame`을 사용하고, 물리 계산은 60Hz 고정 시간 단계로 실행한다.

```javascript
const FIXED_DT = 1 / 60;
let previousTime = performance.now();
let accumulator = 0;

function frame(currentTime) {
  const frameTime = Math.min((currentTime - previousTime) / 1000, 0.25);
  previousTime = currentTime;
  accumulator += frameTime;

  while (accumulator >= FIXED_DT) {
    game.update(FIXED_DT);
    accumulator -= FIXED_DT;
  }

  game.render(accumulator / FIXED_DT);
  requestAnimationFrame(frame);
}
```

탭 전환이나 창 이동 후 누적된 시간을 한 번에 계산하지 않도록 한 프레임의 최대 경과 시간을 0.25초로 제한한다.

## 10. 데이터 구성

레벨은 사각형 배열로 정의한다.

```javascript
const LEVEL = {
  width: 2400,
  height: 720,
  spawn: { x: 100, y: 580 },
  platforms: [
    { x: 0, y: 650, width: 520, height: 70 },
    { x: 620, y: 570, width: 180, height: 30 },
  ],
  goal: { x: 2250, y: 530, width: 48, height: 120 },
  deathY: 780,
};
```

이미지나 외부 레벨 파일은 사용하지 않는다. 숫자 수정만으로 발판 위치와 크기를 조정할 수 있게 한다.

## 11. 작업 순서

1. `index.html`, `styles.css`, `src/game.js` 생성
2. Canvas 크기와 기본 게임 루프 구현
3. 키 입력 상태 구현
4. 플레이어 수평 이동과 중력 구현
5. 사각형 지형 충돌 구현
6. 점프와 가변 점프 구현
7. 코요테 타임과 점프 버퍼 구현
8. 그레이박스 레벨 데이터 작성
9. 낙사와 리스폰 구현
10. 도착점과 클리어 UI 구현
11. 카메라와 디버그 표시 추가
12. 서로 다른 주사율과 창 크기에서 테스트

각 단계는 브라우저에서 실제 실행되는 상태로 유지한다.

## 12. 완료 조건

다음 조건을 모두 만족하면 최소 MVP가 완료된 것이다. 2026-10-07 자동 검증 결과를 반영했다.

- [x] `index.html`을 열면 외부 설치 없이 게임이 시작된다.
- [x] 자동 플레이 중 개발자 콘솔에 오류가 없다.
- [x] 키보드로 좌우 이동과 점프가 가능하다.
- [x] 모바일 터치로 이동과 점프를 동시에 조작할 수 있다.
- [x] 390×844 세로 화면과 844×390 가로 화면에서 조작 버튼이 Canvas와 겹치거나 화면 밖으로 잘리지 않는다.
- [x] 짧게 누른 점프와 길게 누른 점프의 높이 차이가 명확하다.
- [x] 발판을 벗어난 직후 코요테 타임 안에서 점프할 수 있다.
- [x] 착지 직전에 누른 점프가 점프 버퍼를 통해 착지 직후 실행된다.
- [ ] 전체 스테이지를 직접 플레이했을 때 지형 통과나 벽 끼임이 없다.
  - 기본 바닥 착지와 사각형 충돌 자동 검증은 통과했다.
  - 모든 발판 모서리와 연속 점프 구간은 수동 플레이 확인이 필요하다.
- [x] 낙사 후 1초 안에 시작 지점에서 다시 조작할 수 있다.
- [x] 도착점에 닿으면 조작이 잠기고 클리어 문구가 표시된다.
- [x] `R` 키 또는 다시 플레이 버튼으로 스테이지를 재시작할 수 있다.
- [ ] 실제 60Hz 및 120Hz 이상 디스플레이에서 게임 속도와 점프 결과가 의미 있게 달라지지 않는다.
  - 고정 60Hz 물리 루프 적용은 확인했다.
  - 실제 서로 다른 주사율 장치에서의 최종 비교가 필요하다.
- [x] 오류 없이 10회 연속 재시작할 수 있다.

현재 상태는 **기능 구현 완료, 최종 수동 QA 2항목 남음**이다. 남은 확인 절차는 [`NEXT_STEPS.md`](./NEXT_STEPS.md)에 정리한다.

## 13. MVP 이후 첫 확장 순서

1. 경사로와 경사면 충돌
2. 체크포인트
3. 체력과 가시 피해
4. 순찰형 적과 밟기
5. 수집물
6. 스프라이트, 애니메이션, 사운드
7. 메뉴와 저장

MVP 테스트에서 이동 자체가 만족스럽지 않으면 확장 기능을 추가하지 않고 이동 값과 레벨 치수를 먼저 조정한다. 구체적인 다음 작업과 경사로 완료 조건은 [`NEXT_STEPS.md`](./NEXT_STEPS.md)를 따른다.
