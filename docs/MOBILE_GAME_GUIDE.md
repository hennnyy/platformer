# 모바일 조작 코드 이해하기

이 문서는 게임을 처음 보는 개발자를 위해 모바일에서 캐릭터를 움직이고 점프할 수 있는 코드의 흐름을 설명합니다. 터치 버튼을 화면에 배치하는 일과 버튼 입력으로 실제 게임을 움직이는 일은 서로 다른 파일이 담당합니다.

## 먼저 보는 전체 흐름

모바일에서 오른쪽 버튼을 누르는 경우를 예로 들어 보겠습니다.

1. [index.html](../index.html#L50)에 `data-action="right"` 버튼이 있습니다.
2. [styles.css](../styles.css#L171)는 모바일·터치 환경에서 조작 버튼을 화면에 표시합니다.
3. [InputState](../src/game.js#L186)가 버튼의 `pointerdown` 이벤트를 받아 `right` 입력을 켭니다.
4. 게임 루프가 그 입력을 [Player.update](../src/game.js#L425)에 전달합니다.
5. 플레이어가 오른쪽으로 가속하고, Canvas에 새 위치가 그려집니다.

핵심은 **터치 입력도 키보드 입력과 같은 게임 입력 상태(`left`, `right`, `jump`)로 바꾼다**는 점입니다. 플레이어 물리 코드는 입력이 터치에서 왔는지 키보드에서 왔는지 알 필요가 없습니다.

## 각 파일의 역할

| 파일 | 역할 |
| --- | --- |
| [index.html](../index.html#L50) | 왼쪽, 오른쪽, 점프, 재시작 버튼을 만들고 각 버튼에 `data-action` 이름을 붙입니다. |
| [styles.css](../styles.css#L171) | 버튼의 위치와 크기, 눌림 표시를 꾸미고 터치 기기에서만 조작부를 보이게 합니다. |
| [src/game.js](../src/game.js#L186) | 버튼 터치를 게임 입력으로 바꾸고, 입력에 따라 플레이어를 움직입니다. |

## 1. HTML: 버튼에 행동 이름 붙이기

HTML의 모바일 조작부는 `id="mobile-controls"`인 부모 요소 안에 있습니다. 버튼마다 `data-action` 값이 달라서 JavaScript가 어떤 버튼인지 구분할 수 있습니다.

```html
<button data-action="left">←</button>
<button data-action="right">→</button>
<button data-action="restart">↻</button>
<button data-action="jump">JUMP</button>
```

`data-action`은 HTML 요소에 임의의 데이터를 붙이는 표준 방식입니다. JavaScript에서는 `button.dataset.action`으로 읽습니다. 예를 들어 오른쪽 버튼은 `"right"`라는 문자열을 반환합니다.

각 버튼에는 `aria-label`도 있습니다. 화면에 보이는 화살표나 기호만으로 의미를 전달하기 어려운 보조 기술 사용자에게 버튼의 목적을 알려줍니다.

## 2. CSS: 작은 화면에서 조작부 보여 주기

`styles.css`의 `.mobile-controls`는 기본적으로 `display: none`이라 데스크톱에서는 숨겨집니다. 다음 미디어 쿼리가 터치 중심 기기에서 조작부를 표시합니다.

```css
@media (hover: none), (pointer: coarse) {
  .mobile-controls {
    display: flex;
  }
}
```

- `hover: none`: 손가락처럼 마우스 포인터를 올려 두기 어려운 입력 환경인지 확인합니다.
- `pointer: coarse`: 손가락처럼 정밀도가 낮은 포인터인지 확인합니다.

버튼 크기는 `clamp(56px, 14vw, 84px)`처럼 지정되어 있습니다. 화면 너비에 따라 크기가 바뀌되, 너무 작거나 커지지 않도록 최소·최대 크기를 제한합니다.

`touch-action: none`은 버튼을 누르고 움직일 때 브라우저가 페이지 스크롤이나 확대 제스처로 처리하지 않도록 합니다. `env(safe-area-inset-...)` 여백은 노치나 화면 모서리에 버튼이 가려지지 않게 도와줍니다.

## 3. JavaScript: 터치를 입력 상태로 바꾸기

### 초기화

`InputState` 생성자는 `#mobile-controls`를 찾아 `bindTouchControls`에 전달합니다. 컨테이너가 없으면 터치 버튼 연결만 건너뛰고 키보드 입력은 계속 사용할 수 있습니다.

`bindTouchControls`는 컨테이너 안에서 `[data-action]`인 버튼을 찾고 각 버튼에 포인터 이벤트를 등록합니다. Pointer Events를 사용하므로 터치와 마우스 입력을 비슷한 방식으로 처리할 수 있습니다.

### 버튼을 누를 때: `pointerdown`

버튼을 누르면 다음 일이 일어납니다.

1. `event.preventDefault()`로 브라우저의 기본 스크롤·제스처 동작을 막습니다.
2. `button.dataset.action`으로 `left`, `right`, `jump`, `restart` 중 어떤 행동인지 확인합니다.
3. `event.pointerId`와 버튼 정보를 `touchPointers` 맵에 저장합니다.
4. `setPointerCapture(pointerId)`를 호출합니다. 누른 손가락이 버튼 밖으로 움직여도 그 손가락의 놓기 이벤트를 계속 받을 수 있습니다.
5. 버튼에 `is-pressed` 클래스를 붙여 눌린 모양을 표시합니다.
6. 일반 조작은 `setTouchAction(action, true)`로 입력 상태에 반영합니다. 재시작은 `restartPressed`를 켭니다.

`touchPointers`는 `pointerId`를 키로 사용합니다. 손가락마다 ID가 다르므로 이동 버튼과 점프 버튼을 서로 다른 손가락으로 동시에 누르는 멀티터치를 추적할 수 있습니다.

### 버튼을 놓을 때: `pointerup` 등

손가락을 놓으면 `pointerup`이 발생합니다. 전화 알림이나 시스템 제스처처럼 터치가 정상적으로 끝나지 않는 경우를 위해 `pointercancel`과 `lostpointercapture`도 같은 정리 함수에 연결되어 있습니다.

`releaseTouchPointer`는 해당 손가락을 맵에서 지우고, 같은 행동을 누르고 있는 다른 손가락이 없는지 확인합니다. 다른 손가락도 같은 행동을 계속 누르고 있다면 입력을 유지하고, 마지막 손가락까지 놓았을 때에만 입력을 끕니다. 이렇게 하면 포인터 이벤트 하나가 끝났다는 이유만으로 여전히 누르고 있는 입력이 취소되지 않습니다.

### 점프 입력은 누른 순간과 누르는 동안을 따로 기록

`jump`와 `jumpPressed`는 역할이 다릅니다.

- `jump`: 점프 버튼을 현재 누르고 있는지 나타냅니다. 누르고 있는 동안 점프 높이를 계산할 때 쓰입니다.
- `jumpPressed`: 이번 물리 업데이트에서 새로 눌렀는지 나타내는 일회성 신호입니다. 점프 시작을 한 번만 요청합니다.
- `jumpReleased`: 점프 버튼을 놓았는지 나타내며, 상승 중 일찍 놓으면 낮게 점프하는 데 사용됩니다.

입력 후에는 `finishPhysicsStep`이 `jumpPressed`와 같은 일회성 값을 초기화합니다. 반면 `jump`는 손가락을 놓을 때까지 유지됩니다.

## 4. 입력을 플레이어 움직임에 연결하기

`InputState.axis`는 방향 입력을 숫자 하나로 합칩니다.

| 왼쪽 입력 | 오른쪽 입력 | `axis` 결과 |
| --- | --- | ---: |
| 누름 | 놓음 | `-1` |
| 놓음 | 놓음 | `0` |
| 놓음 | 누름 | `1` |
| 누름 | 누름 | `0` |

`Player.update`는 이 값을 목표 속도로 바꾸고 가속도를 적용합니다. 따라서 터치 입력도 키보드와 같은 가속, 감속, 공중 이동, 충돌 처리를 거칩니다. 점프 입력 역시 기존 점프 버퍼와 코요테 타임 규칙에 연결되어 있어 착지 직전이나 발판을 막 떠난 순간의 입력을 허용합니다.

고정 시간 간격으로 실행되는 게임 루프가 입력을 계속 확인하므로, 버튼을 누른 동안 캐릭터가 움직이고 놓으면 감속합니다. 화면을 그리는 코드와 물리를 계산하는 코드는 분리되어 있습니다.

## 5. 키보드와 터치가 같은 게임에 연결되는 방식

키보드는 `actionForCode`에서 키를 게임 행동으로 바꿉니다. 예를 들어 `ArrowRight`와 `KeyD` 모두 `"right"`가 됩니다. 터치 버튼도 `data-action="right"`를 같은 `"right"` 입력 상태에 기록합니다.

두 입력 방식의 결과는 동일한 `left`, `right`, `jump` 상태입니다. 그래서 키보드 지원을 유지한 채 모바일 조작을 추가할 수 있고, 플레이어 물리 코드를 입력 방식별로 복제할 필요가 없습니다.

## 6. 입력이 계속 눌린 상태로 남지 않게 하기

브라우저 탭을 바꾸거나 앱이 백그라운드로 가면 키를 놓는 이벤트를 받지 못할 수 있습니다. `window`의 `blur` 이벤트에서 `clearHeld`를 실행해 이동·점프 상태와 추적 중인 터치 포인터를 모두 지웁니다.

`pointercancel`과 `lostpointercapture`도 개별 터치 입력을 정리합니다. 이 정리 단계가 없으면 손가락을 놓았는데도 캐릭터가 계속 움직이는 문제가 생길 수 있습니다.

## 직접 확인해 볼 테스트

- 휴대폰에서 왼쪽·오른쪽 버튼을 각각 눌렀을 때 캐릭터가 해당 방향으로 움직이는지 확인합니다.
- 방향 버튼을 누른 채 다른 손가락으로 점프를 눌러 동시에 이동과 점프가 되는지 확인합니다.
- 점프 버튼을 짧게 누르거나 길게 눌렀을 때 점프 높이가 달라지는지 확인합니다.
- 버튼을 누른 채 손가락을 버튼 밖으로 옮긴 다음 놓아도 입력이 해제되는지 확인합니다.
- 버튼을 누른 채 브라우저 탭을 전환한 뒤 돌아왔을 때 입력이 눌린 채 남지 않는지 확인합니다.
- 재시작 버튼으로 시작 위치와 스테이지 기록이 초기화되는지 확인합니다.

## 꼭 기억할 요점

모바일 지원을 위해 플레이어 물리를 새로 만든 것이 아닙니다. 화면 버튼을 만들고, 터치를 기존 키보드 입력과 같은 상태로 바꾸는 연결을 추가한 것입니다. 화면 표시와 버튼 모양은 HTML/CSS가, 입력 해석과 게임 규칙은 JavaScript가 담당합니다.
